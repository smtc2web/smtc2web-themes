# AGENTS.md

Vue 3 SPA (`src/`) + Cloudflare Worker API (`server/index.ts`) for the smtc2web theme store (https://themes.smtc2web.org), deployed as a single Worker via `@cloudflare/vite-plugin` and Wrangler. One package, no workspace sub-packages.

## Commands

- `pnpm dev` — Vite dev server; the Worker and local D1/R2 run in workerd alongside it.
- `pnpm type-check` — `vue-tsc --build` over three TS projects (app / node / worker). A type error fails the build.
- `pnpm test` — `node --test server/archive.test.ts` (no test framework; relies on Node ≥22.18 TS type stripping).
- `pnpm build` — runs `type-check` and `vite build` in parallel; `pnpm deploy` — build, then `wrangler deploy`.
- `pnpm db:migrate:local` / `pnpm db:migrate:remote` — apply `server/migrations` to D1. Run the local one once before `pnpm dev`.
- `pnpm cf-typegen` — regenerate `worker-configuration.d.ts` after changing bindings/vars in `wrangler.jsonc`.

No lint or formatter tooling exists; do not invent commands. Node `^22.18.0 || >=24.12.0` is required.

## Bindings and config

- D1 `DB` (database `smtc2web-themes`) and R2 `THEMES_BUCKET` (bucket `smtc2web-themes`, private — downloads stream through the Worker for counting).
- Secrets `GITHUB_CLIENT_SECRET` and `SESSION_SECRET` are not in `wrangler.jsonc`; they are declared in `server/env.d.ts` and set with `wrangler secret put`. Local dev uses `.dev.vars` (gitignored; see `.dev.vars.example`).
- Vars `GITHUB_CLIENT_ID`, `ADMIN_GITHUB_LOGINS`, `OIDC_AUDIENCE`, `OIDC_WORKFLOW_REF` live in `wrangler.jsonc`; custom domain route `themes.smtc2web.org`.

## Architecture notes

- `server/index.ts` routes `/api/*` with native `URLPattern`; `server/auth.ts` is browser GitHub OAuth (HMAC-signed session cookie, no session table).
- Two publish paths share `server/publish.ts` + `server/archive.ts`: web ZIP upload (`POST /api/themes`, session auth) and GitHub Actions OIDC (`POST /api/actions/publish`, verified by `server/actions-auth.ts`: JWKS signature, audience, `job_workflow_ref` must match `OIDC_WORKFLOW_REF`). Theme ownership binds to `source_repo_id`, so only the publishing repo (or the original web uploader) can push new versions.
- `theme.toml` inside the ZIP is the authoritative metadata source (`[smtc2web.theme]`: name/version/author/description/repository/tags/icon/screenshot). Validation mirrors the app's `theme_manager.rs`: exactly one root folder containing `theme.toml`.
- Public catalog API (`GET /api/themes`, `/api/themes/:slug`, `/api/tags`, `.../screenshot`, `.../download`) sends `Access-Control-Allow-Origin: *` — it is the contract consumed by smtc2web v0.7.0.
- `worker-configuration.d.ts` is generated by Wrangler — never hand-edit it.
- `assets.not_found_handling: "single-page-application"` plus the 2026-09-16 compatibility date means browser navigation requests never reach the Worker (they get `index.html`), **except** the paths listed in `assets.run_worker_first` (`/api/*` — without this, every `/api/*` request, navigation or not, is served `index.html` by the SPA fallback). All API calls therefore go through `run_worker_first`; the SPA is served for every non-API path.
